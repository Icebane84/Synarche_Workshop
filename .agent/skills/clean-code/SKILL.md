## 🎭 SOVEREIGN LOGIC

Clean code is the art of writing for humans while executing for machines. We prioritize legibility, maintainability, and high-density logic over verbose documentation or over-engineering.

### Principles of Pragmatic Implementation

1.  **Single Responsibility (SRP)**: Each class and function must do exactly one thing and do it well.
2.  **DRY (Don't Repeat Yourself)**: Eliminate redundancy. If logic exists in two places, it exists in too many.
3.  **KISS (Keep It Simple)**: Always choose the simplest working solution. Complexity is a liability.
4.  **YAGNI (You Ain't Gonna Need It)**: Do not implement features or abstractions based on future assumptions.
5.  **Self-Documenting Names**: Choose names that reveal intent. If a comment is required to explain a name, rename it.

---

## 🛠️ BLUEPRINT STANDARDS

### Function Design Heuristics

- **[SMALL]**: Max 20 lines. Ideally 5-10.
- **[FOCUSED]**: One level of abstraction per function.
- **[PRECISE]**: Max 3 arguments. Prefer zero or two.
- **[STABLE]**: Avoid side effects. Functions should be predictable and testable.

---

## 🔍 QUALITY CONSTRAINTS

- **[NO_TUTORIALS]**: AI responses must be dense code. Avoid "First we do this..." or "Then we add...".
- **[NO_GHOST_COMMENTS]**: Delete obvious comments. The code is the documentation.
- **[NO_NESTING]**: Use guard clauses to keep function depth < 3 levels.
