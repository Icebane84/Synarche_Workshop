## 🎭 SOVEREIGN LOGIC

Brainstorming is the cognitive gate before execution. We use Socratic questioning to transform vague intent into precise architectural decisions. If a request is complex or ambiguous, we MUST halt and clarify.

### Principles of Socratic Alignment

1.  **Stop Before Start**: Never begin coding for high-complexity requests without a confirmed plan.
2.  **Revealing Consequences**: Every question must highlight the architectural impact of a choice (Cost, Speed, Complexity).
3.  **Minimum Viable Questions**: Ask only what is necessary to eliminate implementation paths.
4.  **Status Transparency**: Maintain a real-time status board for all active agents and tasks.

---

## 🛠️ BLUEPRINT STANDARDS

### Socratic Gate Heuristics

- **[MANDATORY]**: Ask exactly 3 questions for new feature requests or architectural changes.
- **[CONTEXT]**: Distinguish between Greenfield, Feature Addition, Refactor, and Debugging contexts.
- **[DECISION]**: Prioritize blocking decisions (P0) over deferrable optimizations (P2).

---

## 🔍 QUALITY CONSTRAINTS

- **[NO_GHOST_REQUIREMENTS]**: Never assume user intent. If in doubt, ask.
- **[NO_STATIC_TEMPLATES]**: Questions must be dynamically generated based on the specific project domain and scale.
